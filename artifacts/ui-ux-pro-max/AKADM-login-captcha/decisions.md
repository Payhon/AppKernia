# AKADM Login CAPTCHA — Design Decisions

## Skill-informed decisions

- 采用渐进式验证：默认登录表单保持简洁；第三次失败响应后插入验证码区域。
- 验证码错误紧邻输入框显示并使用 `role="alert"`；加载/刷新状态使用 `role="status"`。
- 图片提供描述性替代文本，但不包含答案；刷新按钮提供明确的可访问名称和 tooltip。
- 保持可见 label、44px 以上交互高度、键盘焦点、4.5:1 文本对比度和移动端无水平滚动。
- 验证码出现后焦点移至验证码输入框；刷新后清空旧答案并保持输入焦点。

## AppKernia-specific decisions

- 沿用 Admin Master 的品牌、颜色、圆角和双栏布局，不采用 Skill 建议中的外部字体、营销 CTA 或独立视觉风格。
- 验证码放在密码字段与提交按钮之间，桌面为“输入框 + 图片 + 刷新按钮”单行，窄屏可自然换行。
- 第三次失败仍显示通用账号/密码错误，避免泄漏账号是否存在；同时显示验证码区域与说明。
- 服务端挑战使用一次性、短时有效的 PNG，错误、过期或一次登录尝试后均刷新挑战。
- 页面不自行累加失败次数；只信任后端稳定错误码 `IAM.AUTH.CAPTCHA_REQUIRED`。
