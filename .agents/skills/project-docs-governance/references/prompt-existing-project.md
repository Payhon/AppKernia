# 已有代码项目：文档治理补建提示词

你是本项目的编码智能体（Codex、GLM5、Claude Code 或同类工具）。当前项目已有代码，但缺少统一文档管理规范。请在不破坏现有代码、目录、文档和智能体规则的前提下，先盘点真实项目，再增量补齐“文档优先”治理体系。除非我明确指定其他语言，新增文档使用中文，必要技术术语可中英并列。

## 一、先只读盘点

在写入前检查：项目根目录、版本库状态、构建/依赖清单、主要源码目录、入口、测试、部署配置、已有 `docs/`、`AGENTS.md`/`CLAUDE.md` 及同类规则。只记录能从仓库证实的事实；无法确认的内容标记 `<待确认>`，不得推测为已完成。

将盘点结果写入 `docs/02-architecture/current-state-baseline.md`，区分：自动发现事实、已有文档链接、待人工确认项。该基线是初始目录级盘点，不等同于完整架构审计。

## 二、增量建立文档层级

在项目根目录补齐 `docs/`：

- `00-governance/`：原则、工作流、分类层级、命名版本、状态流转、模板。
- `01-product/`：项目说明、路线图、需求。
- `02-architecture/`：当前状态、架构、数据、接口、安全、ADR。
- `03-development/`：开发约定和工作项目录。
- `04-project-tracking/`：看板、里程碑、风险阻塞、变更记录。
- `05-quality/`：测试策略、报告和质量门禁。
- `06-operations/`：部署、运维、监控和事故复盘。
- `07-reference/`：术语和外部资料。
- `08-archive/`：废弃/历史文档及替代关系。

创建或补齐 `docs/README.md` 全局索引。已有文档默认保留原位并登记链接，不因采用新层级而擅自移动、重命名、合并或覆盖。

## 三、后续所有开发项的强制闭环

每个功能使用 `docs/03-development/features/FEAT-xxxx-<slug>/`，包含：

- `00-feature-spec.md`
- `01-technical-design.md`
- `02-implementation-plan.md`
- `03-implementation-log.md`
- `04-test-report.md`
- `05-release-and-handoff.md`

BUG、CHORE、SEC 等工作可使用相同结构和编号前缀。任何代码、配置、数据、接口、依赖或部署修改开始前，必须先创建/更新对应工作项规格并写清验收标准。过程中记录真实实现和偏差；结束时回写测试证据、发布/回滚、已知问题和交接信息。

## 四、项目看板和状态

创建 `docs/04-project-tracking/board.md`，栏目为 Backlog、Ready、In Progress、Review、Blocked、Done。每条必须记录 ID、标题、负责人、优先级、状态、依赖、目标日期、阻塞、工作项文档链接、最近更新时间。

状态统一：`draft -> ready -> in_progress -> review -> done -> archived`；阻塞时使用 `blocked`。看板是状态主事实源，工作项目录是细节主事实源。不要根据存在代码就擅自把历史功能标为 Done；历史功能是否补档应进入待梳理清单。

## 五、合并 AGENTS.md 约束

以唯一受管标记块增量写入根 `AGENTS.md`，保留已有框架规则、命令、风格和安全约束。新增规则必须覆盖：

- 开发前读取索引、看板、相关架构和工作项文档。
- 无规格与验收标准不得编码。
- 实施日志、技术设计、测试、发布/交接与看板的更新触发条件。
- 文档分类、命名、编号、状态、责任人、归档和链接规则。
- DoD：代码、测试、文档、看板、发布/回滚五方面一致。
- PR/提交检查：文档影响、验证命令、验证环境、未验证边界。
- 静态检查、构建、模拟环境、生产环境、真实设备验收必须明确区分。
- 不得虚构历史、需求、验证结果或线上状态。

## 六、已有项目专属安全规则

- 默认只创建缺失文件；同名已有文件列为“保留”。
- 不修改业务代码，不整理无关脏工作树，不覆盖现有文档。
- 若确需迁移旧文档，先提出映射和风险，获得明确授权后另行执行。
- 将本次治理初始化记录为独立已完成工作项；将“历史文档与功能盘点”置于 Backlog，不虚构历史完成情况。
- 重复执行必须幂等；仅可自动替换自身受管标记块。

## 七、验收与报告

完成后运行只读完整性检查，确认索引、治理规范、模板、六类工作项文档、看板、质量/运维目录和闭合的 AGENTS.md 受管块均存在。

最终报告分开列出：检测模式及证据、已创建文件、已更新文件、原样保留文件、未改动的代码、待人工确认项、检查结果。不得把目录级盘点称为完整架构审计，不得把模板创建称为历史功能已补档。

完成治理补建后，再选择一个真实的下一开发项，从规格文档开始推进。
