# Decisions

- Preserve existing neutral AppKernia Admin tokens rather than adopting the skill's generic marketing palette or external typography.
- Use an application context strip and typed `app_id` URL selection to make the server-side App boundary visible and shareable.
- Use semantic status tags plus text, RHF-backed labelled fields, and async button feedback.
- Keep protected legal pages non-deletable in both visible controls and confirmation paths; server authorization remains authoritative.
- Reuse the existing article/category editor for the legacy System routes and render explicit legacy/shared scope semantics there.
